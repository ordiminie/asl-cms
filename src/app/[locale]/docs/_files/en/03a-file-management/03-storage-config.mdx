Files live on the **server disk** (ADR 004). The `local` adapter is the only implemented provider
and the default; the factory keeps the door open for a second one.

## Disk Storage Setup

<Steps>
<Step title="Create the storage root">
  ```bash
  sudo mkdir -p /var/lib/asl-cms/files
  sudo chown -R app:app /var/lib/asl-cms/files
  ```

  The directory must live **outside `public/`**: stored files are never served
  straight from the filesystem, always through an application route.
</Step>

<Step title="Point the application at it">
  ```bash
  # .env.local
  LOCAL_STORAGE_ROOT=/var/lib/asl-cms/files

  # Optional: `local` is the only accepted value, and the default
  STORAGE_TYPE=local

  # Generic validation for the file chain
  NEXT_PUBLIC_MAX_FILE_SIZE=5242880
  NEXT_PUBLIC_ALLOWED_MIME_TYPES=image/jpeg,image/png,image/gif,application/pdf
  ```
</Step>

<Step title="Back it up">
  The storage root is state, like the database: include it in the server backup.
</Step>
</Steps>

```typescript
    bucket: STORAGE_BUCKET,

```

<Callout type="warning">
  `files-repository.ts` builds its storage **when the module loads**, not on
  call: a configuration error surfaces when a page importing it renders, not
  when a file is uploaded.
</Callout>

## Storage Factory Pattern

```typescript
// src/lib/files/storage/storage-factory.ts
export type StorageType = 's3' | 'local'

export const createStorage = (
  type: StorageType,
  config: StorageConfig
): StorageOperations => {
  switch (type) {
    case 'local':
      return createLocalStorage(config, env.LOCAL_STORAGE_ROOT)
    case 's3':
      throw new Error('S3 provider not implemented yet')
    default:
      throw new Error(`Unknown storage provider: ${type}`)
  }
}

export type StorageConfig = {
  bucket: string
  basePath: string
  maxFileSize: number
  allowedMimeTypes: string[]
}

export type StorageOperations = {
  upload: (file: File, path: string) => Promise<{path: string}>
  download: (path: string) => Promise<Blob>
  delete: (path: string) => Promise<void>
  list: (path: string) => Promise<StoredFile[]>
}
```

`StoredFile` is a neutral type (`{name, size, mimeType?}`): no provider imposes
its own shape on the rest of the codebase.


Two rules the adapter enforces, and that callers must not work around:

- **Every key is confined under `rootDir/basePath`.** An empty key, a null byte,
  an absolute path, a `..` segment or anything resolving outside the root is
  rejected with `INVALID_PATH`.
- **Keys are generated by the server**, never taken from a user-supplied
  filename.

## Path and URL

```typescript
// Generated by file-service.ts
// posts/{postId}/image/{timestamp}-{filename}
```

A stored file has **no public URL**: it is served by an application route
(see `GET /api/identity/{logo|favicon}` for the association identity files).
`FileResponse.url` carries the storage key.

## Future Provider

The `s3` branch of the factory throws today. Implementing it means writing
`createS3Storage(config)` against the same `StorageOperations` contract and
adding the value to both the `StorageType` union and the `STORAGE_TYPE` enum —
nothing else in the codebase has to change.

## Testing

Unit tests replace the adapter root with a temporary directory rather than
mocking the filesystem:

```typescript

```
